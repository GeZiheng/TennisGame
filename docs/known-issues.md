# 已知问题与设计脆弱点

> 原为 `AGENTS.md` 第 7 节，2026-11-09 拆分独立成篇。这些是**已知的、故意没改的**——不要误以为是新 bug。
>
> 例外：7.1 是最高优先级，症状本身还没被解决，处理方式见 `AGENTS.md` 第 0 节。

## 7.1 真机症状未确认（最高优先级）

真机症状是「挥拍时球从拍面穿过」。当前代码是「球追拍面」的缓解方案，**不是被验证的修复**。见 `AGENTS.md` 第 0.3 / 0.4 节。

## 7.2 注释与实现不一致（低风险，但会误导）

1. `src/core/rally.ts` 的 `serve()` 注释里还留着「拍面锚定之后，握点是绕拍面中心甩的」——锚定已经撤销。同段还有「球在玩家前方 1.6–2.05 米落地」和「取 0.16 / 0.14」，实际是 **1.55–1.85m** 和 **0.12 / 0.10**。
2. `src/core/physics.ts` 的 `feedBounce` 文档写「落点为什么在 1.6–2.05 米」，实际由 `court.ts` 的 `FEED_APEX_LEAD − back` 决定，是 1.55–1.85m。
3. `src/core/racket.ts` 顶部注释还写着「球心穿过平面是球体撞上拍面的必要条件……既不漏也不多」，这是旧判据的论证；实现已经改成盘形候选点判据（`sweepFace` 的函数注释是新的，顶部文件注释没同步）。
4. `README.md` 里「落点距拍面 1.2m → 顶点在拍面后 1.1m」等表格数值来自不同时期的实测，量级对但个别数字和当前 `probe-feed-scan2` 输出不完全一致。

**改代码时顺手同步这些注释，但不要为了同步注释而改行为。**

## 7.3 设计上仍然脆弱的地方

1. **球追拍面是「辅助瞄准」**。`STEER_VMAX=12` 已经很大（球速 7 m/s 时能偏折 60°）。如果真机上感觉球「会拐弯」，说明跟随过强；如果仍然穿模，说明跟随不够或几何另有问题。这是一个需要真机调的平衡，不是纯代码问题。
2. **击球高度依赖姿态**。`serve` 用来球高度 = `clamp(faceCenter.y, 0.8, 1.9)`，玩家把手机举高/放低，来球高度会跟着变。锚定方案取消后，这块又回到「跟着姿态走」。
3. **`liftOverNet` 的 `probe` 很贵**（一次回球 ~33 条候选 × 每条最多 1600 步）。目前只在击球时算一次，可以接受；如果以后要加「落点预览」之类的实时功能，需要缓存或降采样。
4. **`RacketTrack.at()` 是线性扫描**（最多 24 个元素）。当前 240Hz × 400ms 完全够用，不是瓶颈。
5. **`docs/motion-accuracy.md` 的握持标定还没做**。这是零成本、收益最大的一项：静止持拍取平均法线，与期望方向比对求安装角，出球时反向旋转补偿。若出现「球总往一边偏」，先看 HUD 的「拍面」读数。

## 7.4 没有做的事

- 没有角色/手部渲染（只有球拍），所以「拍面中心被甩走」在视觉上没有参照物，只能靠球的位置判断。
- 没有真机自动化测试。所有真机结论都来自现场观察 + HUD 读数。
- 没有回放/录像功能。排查「刚才那一拍为什么没打到」只能靠 HUD 的六个瞬时值。
