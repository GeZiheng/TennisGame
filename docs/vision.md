# docs/vision.md · 摄像头视觉走位（实验通道）

> 最后更新：2026-11-10。**默认关闭，尚未经过任何真机验证。**
> 本册只讲 `?vision=...` 这条实验输入；击球判定、弹道、喂球仍看 `docs/algorithms.md`。

## 1. 为什么加这条通道

键盘走位要求玩家一只手拿手机、另一只手按 `WASD`。想让站位由身体动作决定，
最直接的念头的「用手机 IMU 推位置」，但那条路在本项目里是死的：

| 想过 / 否掉的 | 结论 |
|---|---|
| 手机加速度二次积分 | 重力泄漏（β/γ 静态误差 1–2° → 假加速度 0.17 m/s²）+ MEMS 零偏，静止 10 秒漂 0.5–8m；挥拍时 2–4g 与走位 0.05–0.2g 混在同一轴，ZUPT 无法区分「人在走」和「手在挥」 |
| 离散步进 PDR | 误差有界，但挥拍阈值仍需真机标定，且给不了「伸拍 20cm」 |
| 华为手环原始 ACC | `Wear Engine` 的运动传感器仅企业开发者 / 专业机构开放；原生 SDK 要中转 App，打破双端浏览器架构；Band 系列能否订阅不确定 |
| UWB 锚点定位 | 唯一能给出不漂移的绝对位置与前后 z，但要 1 标签 + 3–4 锚点、¥300–500、1–2 周固件与标定。**只要左右时，它不可替代的优势（z）恰恰被需求删掉了** |
| 笔记本摄像头 + 胸口色块 | 0 元、被动标记、不成像人体以外的东西、右手挥拍完全不进入测量链 |

关键简化来自**「先只做左右，不做前后」**：单目平视测前后只能靠透视缩放，
和身体起伏、前倾后仰混在一起，是调参救不了的几何天花板；而左右是干净的像素平移。
去掉 z 之后，剩下的活儿从「解深度」变成「找一维质心」。

## 2. 定案与边界

- **只解一个轴**：色块水平像素质心 → `PLAYER.x`。`PLAYER.z` 固定在 `HIT_Z`。
- **直接映射，不积分**：`x = clamp((cx/(W-1) - 0.5) · 2·maxX, ±maxX)`。
  像素位置是绝对测量，一阶低通只朝目标收敛、不累积误差 —— 这是和 IMU 路线的根本区别。
- **色块丢失时保持上次站位**，不钳到边界。人走出画面 ≠ 站到了最边上。
- **默认完全关闭**：不加参数时 `vision` 为 `null`，`updatePlayer()` 走原来的键盘分支，
  一行行为都没变。`V` 键可在 drive 模式下临时切回键盘做 A/B 对照。
- **不碰 `src/core/`**：新增的是 `src/play/vision-math.ts`（纯计算，进 Node 单测）和
  `src/play/vision.ts`（DOM / 摄像头）。物理、判定、协议一行未改。
- **不要撤掉键盘**：视觉通道是实验对照，不是替换。权限被拒、光线不行、色块丢失时
  键盘就是回退路径。

### 和另外两路走位的关系

11-12 起 `updatePlayer()` 有三路输入，优先级从高到低：**视觉 → 键盘 → 自动**
（`core/auto-move.ts`，默认开）。视觉一旦接管就整帧 `return`，自动走位不会和它抢
`PLAYER.x`；`V` 切回键盘时自动走位同样让位。所以三条不需要额外开关就能共存。

视觉通道解决的问题和自动走位不同：视觉是「**让玩家的身体动作**驱动站位」（人往左走，
拍子往左），自动走位是「**不管人站哪，把拍面搬到球那儿**」。视觉只写 `x`（`z` 固定在击球面），
自动走位写 `x` 和 `z`（11-13 起），两者优先级不同、不并存。

### 明确放宽的硬约束

`AGENTS.md` 0.1 的第 2 条原本是「只用现有手机，0 成本，不加第二个传感器」。
本轮按 11-10 的决定**明确放宽为「允许使用笔记本自带的摄像头」**，
但保持：不新购硬件、不引第三方 CV 库、不写原生 App、不新增需要资质的数据接口。
UWB / 手环 / 独立 IMU 模块均未采用。若将来要重新收紧，删掉这两个 play 文件即可。

## 3. 数据流

```
getUserMedia(320×240, facingMode=user)
  → 每 2 帧 drawImage 到离屏 canvas（约 30Hz）
  → getImageData → buildMask：RGB→HSV，判色相/饱和度/明度
  → largestBlob：4 邻域 BFS 只取最大连通块，面积 < minArea 算丢失
  → mapPixelX：像素质心 → 站位（钳位到 ±maxX）
  → lowPass：τ=250ms，压掉转体与挥拍带来的快变量
  → VisionTracker.x（米）
  → main.ts updatePlayer：drive 模式写 PLAYER.x，setRacketBase()
```

`src/core/` 的 `targetZ` 链**没有删**。`Rally.serve` 里 `targetZ = face ? face[2] : HIT_Z`，
击球面 z 取自当前拍面中心，而拍面中心会随手机姿态前后甩出去（竖挥 30° 约 0.31m）。
键盘的 `PLAYER.z` 走位只是叠加在上面的另一份变化 —— 所以去掉前后走位不需要改 core，
`feedBounce` / `feedVy` / `liftOverNet` 的 `targetZ` 参数是为拍面几何服务的。

## 4. 怎么用

```bash
npm run dev:https     # 摄像头属于安全上下文，必须 HTTPS
# 大屏地址后加参数；手机端 controller.html 不用改
```

> **拼参数别写第二个 `?`**：如果大屏地址已经带了 `?room=XXXX`（指定房间号），
> 后面要用 `&` 拼，例如 `https://<大屏地址>/?room=AB12&vision=probe`；
> `?vision=probe` 这种写法只适用于地址还没有任何 query 的情况。

| 参数 | 默认 | 作用 |
|---|---|---|
| `?vision=probe` | 关 | **只读取证**：右上角显示读数，不接 `PLAYER`。第一步先用这个 |
| `?vision=1`（或 `drive`） | 关 | 接管左右走位，忽略键盘走位，`z` 固定 |
| `?hue=magenta` | `magenta` (310°) | 预设 `magenta` / `green`(75) / `blue`(210) / `yellow`(45) / `red`(0)；也可给 0–360 数字 |
| `?tol=24` | 24 | 色相容差（度），环形距离，跨 0/360 也成立 |
| `?minarea=24` | 24 | 最大连通块的最小像素数，低于它判丢失 |
| `?tau=250` | 250 | 低通时间常数（ms）。调大更稳但跟手变慢 |
| `?range=1.2` | 1.2 | 视觉模式站位半幅（米）。键盘模式仍是 `maxX=3.0` |
| `?flip=1` | 关 | 水平镜像。前置摄像头在部分机型回传镜像帧，方向反了就加它 |
| `?preview=0` | 开 | 关掉取帧预览（调色块时建议开着） |

标记物建议：胸口正中或肩、8–10cm 见方、高饱和、哑光。别挂手腕 —— 转体会让腕部
绕躯干画 0.3–0.5m 的弧，单目分不清「人横移了」和「只是转了个身」。
想更稳可以在墙上贴一块同色固定参照做差分，消掉笔记本被碰一下带来的整体漂移。

HUD 六个读数：`像素质心`、`推算站位`、`色块`、`丢失帧`、`处理帧率`，以及配置行。
预览画面里的竖直中线就是 `PLAYER.x = 0`，绿十字是检出的色块质心。

## 5. 真机取证步骤（**尚未执行**）

1. 先看物理布置：笔记本镜头拍不拍得到人、胸口色块在不在画面里、背景会不会撞色。
   大屏若是外接电视 / 显示器，玩家对着电视站时笔记本镜头可能根本拍不到。
2. `?vision=probe`，往左走一步：`推算站位` 应变负。反了就加 `?flip=1`。
3. 原地站着挥 5 拍：看 `推算站位` 波动。这是决定成败的数字 —— 挥拍污染有没有被
   「只测躯干色块 + 低通」挡住。
4. 左右各走 1m 再回中：看回零误差与 `丢失帧` 是否持续增长。
5. **判据**：中间区稳定到几厘米、挥拍波动 < 0.2m → 可以试 `?vision=1`；
   一挥拍就飘出 0.5m 或丢失严重 → 不要接进走位，退回键盘或改触屏摇杆。

接进去之后还要单独确认一件事：`range=1.2` 把站位半幅从 ±3.0 收窄了，
「走到边上救球」的空间变小。发球仍按当前拍面中心定横向起点、落地重瞄瞄此刻拍面，
所以影响预计有限，但**必须真机打几轮确认**，不能直接改 `maxX` 常量。

> **注意**：`npm run verify` 覆盖不到这条通道：单测跑的是 vision-math 的纯函数，
> sim 跑的是 `src/core/` 的整局对拉，两者都不执行 DOM / 摄像头代码。
> 门禁全绿只说明「默认路径没被改坏、纯计算自洽」，**不代表视觉走位真机可用**。

## 6. 已知限制

- **FOV**：65° 水平视角，站 1.5–2m 只覆盖约 1.9–2.6m 宽。这正是把 `range` 收到
  ±1.2 的原因；站远到覆盖全场，色块在画面里会小到只剩几像素。
- **前后轴没有**：这是明确的取舍，不是遗漏。需要 z 时本方案不够，得回到 UWB / 深度相机。
- **自动曝光 / 白平衡**：用 HSV 而不是 RGB 判色就是为了钝化亮度漂移，但极端光照仍需真机调
  `tol` / `minarea`。纯色上衣与背景撞色会直接失效。
- **遮挡与出画**：保持上次站位。连续丢失时 HUD 会显示累计帧数。
- **镜头被碰**：整体漂移会被读成走位。固定参照色块做差分可消掉，尚未实现。
- **隐私**：预览只在本地内存里画，不上传、不落盘；关掉 `?preview=0` 连显示都没有。
