# 测试说明

> 本篇回答三件事：`tests/` 里测了什么、怎么跑起来、加新测试要守哪些约定。
> 编号接 `docs/known-issues.md` 的 7.x。`docs/tuning.md` 6.3 记的是「测试里踩过的坑」，本篇记的是「测什么、为什么测」，两篇互补。
> 玩家视角的简版在 `README.md` 的「测试」一节。

## 8.1 一句话与运行链路

`tests/` 目录下只有 **一个文件**：`tests/core.test.cjs`，1343 行、**77 项**、13 个分组。它没有用 vitest / jest，而是自带一个 10 行的 `t(name, fn)`（`tests/core.test.cjs:14`）+ `node:assert`：每项单独 try/catch，失败打印 `FAIL` 并设 `process.exitCode`，**不中断**，最后打印「N 项通过」。

理由写在 `scripts/test.mjs` 开头：`src/core/` 刻意不依赖 three.js 和 DOM，这几块逻辑（二进制协议、姿态积分、分位数、时钟同步）编成 CommonJS 就能在 Node 里直接跑，不必多装一套测试框架。

```bash
npm test
# └─ node scripts/test.mjs
#    ├─ tsc 把 11 个 .ts 编到 .tmp-test/{core,play}/*.js（--module commonjs --target es2022）
#    ├─ 写 .tmp-test/package.json = {"type":"commonjs"}（根项目是 ESM，产物必须单独声明）
#    ├─ 把 tests/core.test.cjs 复制成 .tmp-test/run.cjs
#    └─ 以 .tmp-test 为 cwd 执行 run.cjs
```

因此有三件容易踩空的事：

1. 测试里 `require('./core/xxx.js')` 指向的是**编译产物**，不是 `src/`。改完 TS 不重跑 `npm test`，测的还是旧代码。
2. 编译输入是 `scripts/test.mjs` 里**写死的 11 个文件**（`protocol / imu / attitude / vec / court / gyro / swing / racket / physics / rally` + `play/stats`）。**新增 core 模块必须同时加到 `scripts/test.mjs` 和 `scripts/sim.mjs` 的输入列表**，否则 require 不到；两处参数目前逐行相同。
3. `test.mjs` 刻意不删 `.tmp-test/` 目录（删除拦截器会挡递归删除，tsc 会覆盖同名产物）。代价是目录里可能留旧文件：**别写成 `require('./court.js')` 漏掉 `/core/`**，那会静默加载过时物理，症状很像物理 bug。同理 `.tmp-sim/` 是 `npm run sim` 的产物，probe 脚本从那里读编译结果。

改动后的固定流程见 `AGENTS.md` 第 3 节：`npm run verify`（`test` ×3 → `sim` → `build`），`git commit` 前由 `scripts/hooks/pre-commit` 跑快检。probe 依赖 `.tmp-sim`，所以必须排在 `sim` 之后。

## 8.2 验证分工，别混为一谈

| 层 | 入口 | 跑什么 | 能回答什么 | 覆盖不到的 |
|---|---|---|---|---|
| 单测 | `npm test` | 77 项，算子级 + 短场景 | 某个公式、判据、状态机分支对不对 | 整局手感、网络、真机 |
| 端到端模拟 | `npm run sim` | 五档力度 × 6 随机种子，完整对拉 | 参数改了之后还能不能连打、会不会撞网/漏接 | 传感器、渲染、真机姿态 |
| 调参取证 | `scripts/probe-*.cjs` | 扫拍面高度 / 落点 / 转角 / 站位 | 「为什么这个数是这个值」的实测依据 | 不自动判定通过/失败，要人读表 |
| 信令冒烟 | `npm run test:signal` | 两个 WebSocket 客户端走配对→转发→断线 | 房间配对链路通不通 | 需先 `npm run dev`，**不在 `npm test` 里** |
| 真机 | 手机 + 大屏 | 现场观察 + HUD 六个数 | 挥拍时球到底回不回弹 | 无自动化，见 7.4 |

**绿 ≠ 修好了。** 本项目吃过「单测全绿、sim 30/30、真机全漏」的亏（模拟器里球拍曾全程不转，见 `docs/tuning.md` 6.3）。真机症状仍是最高优先级未决项，见 `AGENTS.md` 0.3 与 `docs/known-issues.md` 7.1。

## 8.3 13 个分组，逐组说明

分组由文件里的 `console.log('…')` 标题切分，顺序即执行顺序。

## 8.4 不能删的「反证」

这些断言不是凑覆盖率，每一条都钉住一个已踩过的坑或已否决的方向。**改绿了不等于修好了，把断言放宽来「修绿」尤其危险。**

| 断言 | 钉住什么 | 来龙去脉 |
|---|---|---|
| 一步跨过整个拍面也不漏 | 必须做**线段求交**，不能点判定 | `docs/algorithms.md` 3.5 |
| 掠射也算接触 | 判据是「球心到圆盘距离 ≤ 球半径」，不是「穿过平面」；否则视觉上就是穿模 | `docs/algorithms.md` 3.5 |
| 倾斜拍面下补偿弧线要真穿过盘 | 回球补偿必须与判定共用 `sweepFace`，竖平面对斜拍面差 15cm | `docs/history.md` 4.3 |
| 转 60° 中心扫出 0.45m 以上 | **拍面中心锚定方案已否决**，位置必须留给握点 | `AGENTS.md` 0.5 |
| 球拍一直转仍打得中 | 球在最后 0.55s 跟拍面走的跟随链路；曾经模拟器全程同一个姿态，这条路径 0 覆盖 | `docs/history.md` 4.6、`docs/tuning.md` 6.3 |
| 上旋比平击下坠快 | 马格努斯是 `v × ω`，写成 `ω × v` 上旋会往上飘 | `AGENTS.md` 硬约束 7 |
| 发球必须先落地一次 | 弹地喂球；直送在后场会退化成月亮球，且落点是玩家唯一的计时锚点 | `docs/algorithms.md` 3.6 |
| 没挥拍是擦框掉下去 | 喂球瞄着拍面中心，「没挥」每球都会演一次，演错会被当成碰撞 bug | `docs/algorithms.md` 3.8 |
| 旧版 60 字节包仍可解码 | 手机端页面缓存未刷新时的兼容性 | 协议分组 |

## 8.5 加新测试的约定

**写法**：`t('现象 → 期望', () => { … })`，名字写清「什么情况下应该怎样」，别只写模块名。断言用 `node:assert`；需要固定序列时用文件里已有的 helper：`flatPose` / `strokeAt` / `placeRacket` / `predictX` / `drive` / `feed` / `qAA` / `quatAxis`。`drive()` 按 60fps 推进并返回各类事件计数，整局场景优先复用它。

**时间单位（最容易写错）**：

- `Rally.update(dt, now)`：`dt` 是**秒**，学 `drive()` 传 `1000/60 / 1000`；`now` 是**毫秒**。
- `pose.t` / `stroke.t` / `HIT_WINDOW_MS` / `CONTACT_HOLD_MS` 都是**毫秒**，和 `now` 同一把尺子。
- `ImuTracker.update(gyro, dtMs)`、`SwingDetector` 的 `feed(..., dt=16)` 也是毫秒。
- `physics.advance(ball, dt, onStep)` 的 `dt` 是**秒**，定步长 1/240。

**加模块**：见 8.1 第 2 条，两处编译输入都要加。`onStep` 回调返回 `false` 表示事件已处理，必须 `break`，否则会重复结算。

**场景要像真机，别过度理想化**（详见 `docs/tuning.md` 6.3）：

- 模拟器里球拍**必须真的会转**（绕局部 x 轴，中心扫出 0.3–1.1m）；绕法线转中心不动，等于没测。
- 走位用 `predictX` 做**物理前推**，不能线性外推——落地会削掉约 26% 横向速度；且要限速 0.07m/帧，朝球的**当前**横向走，别做外推。
- 别让「拍面追球」和「球追拍面」两边都完美跟随，会互相带偏成高频振荡，球到面时偏到盘外。
- 样本少的统计断言**不要卡跨度**（4 球的甜区跨度会偶发红），改成「都在盘内 + 不是每球完全一样」。
- 改发球节奏要**放宽所有「等球到面」的窗口**，否则偶发失败，而且看起来像别的问题。

**随机性**：发球 `vx` 带随机散布，某些漏接只在特定扰动耦合下出现。所以 `npm test` **连跑 3 次**才算稳，`npm run sim` 用 6 个种子；单次通过不作数。

## 8.6 没覆盖什么

- **真机挥拍穿模**：没有真机自动化测试，也没有回放/录像；排查只能靠现场观察 + HUD 瞬时读数（`docs/known-issues.md` 7.4）。
- **浏览器侧一切**：传感器事件、WebRTC/信令（除 `test:signal` 冒烟）、HTTPS 证书、three.js 渲染、HUD、手机端 UI，全都不在 `npm test` 里。
- **性能与长稳**：帧率、内存、`liftOverNet` 的计算开销（一次回球约 33 条候选 × 每条最多 1600 步）没有基准测试。
- **位姿是理想化的**：测试走位用物理前推 + 限速，比真人准；姿态用构造的四元数，不含传感器噪声、安装角误差和手部抖动（见 `docs/motion-accuracy.md`）。
- **改常量的联动**：`FACE_*`、`FEED_*`、`HIT_WINDOW_MS` 同时决定判定、喂球和测试期望。改之前先读 `docs/tuning.md` 5.1–5.4，改完按 `AGENTS.md` 第 3 节跑三件事：`npm test` ×3 → `npm run sim`（30/30）→ `npm run build`。
