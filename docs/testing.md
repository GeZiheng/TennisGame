# 测试说明

> 本篇回答三件事：`tests/` 里测了什么、怎么跑起来、加新测试要守哪些约定。
> 编号接 `docs/known-issues.md` 的 7.x。`docs/tuning.md` 6.3 记的是「测试里踩过的坑」，本篇记的是「测什么、为什么测」，两篇互补。

## 8.1 一句话与运行链路

`tests/` 目录下只有 **一个文件**：`tests/core.test.cjs`，**144 项**、25 个分组。它没有用 vitest / jest，而是自带一个 10 行的 `t(name, fn)`（`tests/core.test.cjs:14`）+ `node:assert`：每项单独 try/catch，失败打印 `FAIL` 并设 `process.exitCode`，**不中断**，最后打印「N 项通过」。

理由写在 `scripts/test.mjs` 开头：`src/core/` 刻意不依赖 three.js 和 DOM，这几块逻辑（二进制协议、姿态积分、分位数、时钟同步）编成 CommonJS 就能在 Node 里直接跑，不必多装一套测试框架。

```bash
npm test
# └─ node scripts/test.mjs
#    ├─ tsc 把 17 个 .ts 编到 .tmp-test/{core,play}/*.js（--module commonjs --target es2022）
#    ├─ 写 .tmp-test/package.json = {"type":"commonjs"}（根项目是 ESM，产物必须单独声明）
#    ├─ 把 tests/core.test.cjs 复制成 .tmp-test/run.cjs
#    └─ 以 .tmp-test 为 cwd 执行 run.cjs
```

因此有三件容易踩空的事：

1. 测试里 `require('./core/xxx.js')` 指向的是**编译产物**，不是 `src/`。改完 TS 不重跑 `npm test`，测的还是旧代码。
2. 编译输入有两份列表，**新增 core 模块必须两处都加**，否则 require 不到：`scripts/test.mjs`（编译到 `.tmp-test`）和 `scripts/core.mjs` 的 `CORE_FILES`（编译到 `.tmp-duel`，探针与 `duel-sim` 共用）。11-15 合并之后 `core.mjs` 是唯一一份 core 编译清单，`test.mjs` 那份多了 `play/stats`（只服务单测）——两边不再逐行相同，是刻意的。

3. `test.mjs` 刻意不删 `.tmp-test/` 目录（删除拦截器会挡递归删除，tsc 会覆盖同名产物）。代价是目录里可能留旧文件：**别写成 `require('./court.js')` 漏掉 `/core/`**，那会静默加载过时物理，症状很像物理 bug。同理 `.tmp-duel/` 是 `npm run core` / `npm run duel-sim` 的产物，probe 脚本从那里读编译结果（`npm test` 只产出 `.tmp-test`，**不产出 `.tmp-duel`**）。

改动后的固定流程见 `AGENTS.md` 第 3 节：`npm run verify`（`test` ×3 → `duel-sim` → `build`），`git commit` 前由 `scripts/hooks/pre-commit` 跑快检。probe 依赖 `.tmp-duel`，所以必须先 `npm run core`。

## 8.2 验证分工，别混为一谈

| 层 | 入口 | 跑什么 | 能回答什么 | 覆盖不到的 |
|---|---|---|---|---|
| 单测 | `npm test` | 144 项，算子级 + 短场景 | 某个公式、判据、状态机分支对不对 | 整局手感、网络、真机 |
| 对打模拟 | `npm run duel-sim` | 三档难度 × 6 种子 × 60s，玩家侧是求解器（含发球） | 回球机能不能连续接球、**能不能接得住发球**、难度梯度方向对不对 | 玩家侧不是 `shotFromStroke`，见 `docs/duel.md` 第 8 节 |
| 调参取证 | `scripts/probe-*.cjs` | 扫拍面高度 / 落点 / 转角 / 站位 | 「为什么这个数是这个值」的实测依据 | 不自动判定通过/失败，要人读表 |
| 信令冒烟 | `npm run test:signal` | 两个 WebSocket 客户端走配对→转发→断线 | 房间配对链路通不通 | 需先 `npm run dev`，**不在 `npm test` 里** |
| 真机 | 手机 + 大屏 | 现场观察 + HUD 六个数 | 挥拍时球到底回不回弹 | 无自动化，见 7.4 |

**绿 ≠ 修好了。** 本项目吃过「单测全绿、端到端模拟全过、真机全漏」的亏（模拟器里球拍曾全程不转，见 `docs/tuning.md` 6.3）。真机症状仍是最高优先级未决项，见 `AGENTS.md` 0.3 与 `docs/known-issues.md` 7.1。

## 8.4 不能删的「反证」

这些断言不是凑覆盖率，每一条都钉住一个已踩过的坑或已否决的方向。**改绿了不等于修好了，把断言放宽来「修绿」尤其危险。**

> 11-15 删掉对墙打时，有五条反证（倾斜拍面补偿弧线、球拍一直转仍打得中、发球后走开必然够不着、
> 发球必须先落地一次、没挥拍是擦框掉下去）随被测路径一起没了。它们的**结论仍然成立**，
> 只是没有等价场景可以钉：保留在 `docs/history.md` 里，别因为表里没有就当成「以前搞错了」。

| 断言 | 钉住什么 | 来龙去脉 |
|---|---|---|
| 一步跨过整个拍面也不漏 | 必须做**线段求交**，不能点判定 | `docs/algorithms.md` 3.5 |
| 掠射也算接触 | 判据是「球心到圆盘距离 ≤ 球半径」，不是「穿过平面」；否则视觉上就是穿模 | `docs/algorithms.md` 3.5 |
| 转 60° 中心扫出 0.45m 以上 | **拍面中心锚定方案已否决**，位置必须留给握点 | `AGENTS.md` 0.5 |
| 上旋比平击下坠快 | 马格努斯是 `v × ω`，写成 `ω × v` 上旋会往上飘 | `AGENTS.md` 硬约束 7 |
| 旧版 60 字节包仍可解码 | 手机端页面缓存未刷新时的兼容性 | 协议分组 |

| 高低差靠举拍/屈膝解决，不靠前后跑 | 旧版为了凑「球到面高度」会把玩家拖到底线外 2m，而球最高只到 1.63m——那是无解的平面。高度差必须由握点升降吸收，否则就是「离球太近/太远打不到」 | `docs/history.md` 4.20 |
| 高度不能一帧走完 | `stepAutoMove` 的高度两段（预位 1.8 / 对位 6 m/s）。9 m/s 是一帧 15cm，抬起来是一瞬间、球一过又弹回 1.3m，读起来就是「拍子高度永远不变」 | `docs/history.md` 4.23 |
| 走位瞄的是「球到面那一刻的拍面」，不是「站着不动的拍面」 | 挥拍 40–80° 会把拍面中心扫出去 40–60cm，比判定盘半轴（0.20 / 0.24）还大。`probe-contact.cjs` 量这段缺口：斜握 0.128 → 0.048m | `docs/history.md` 4.23、4.27 |
| 相邻一格交替胜出不许跟着翻 | `holdR` 曾正好等于 `CROSS_STEP`（0.10），相邻候选的代价只差千分之几就翻一次，横向抖到 741–743 帧连翻两次 | `docs/history.md` 4.26 |
| 6cm 的来回改主意必须被吃掉 | 规划器每帧重选平面，相邻候选的代价只差千分之几；不保持的话 `targetZ` 在两格之间跳，人按满速走 6cm 再走回来（60Hz 方波，相机跟着晃）。**注意别去「顺手」把采样网格锚死**——那会丢响应性，横向偏差 0.16 → 0.29m | `docs/history.md` 4.22 |
| 原地翻腕不许搬握点 | 枢轴用**拍柄方向的最小弧**而不是姿态增量；用姿态增量的话一次翻腕就会把拍子甩出去半米 | `docs/algorithms.md` 3.10 |
| 网前的短球要往前迎 | `sampleCrossings` 必须按「两次落地即判死」截断（`bounces >= 2 && at[2] > NET_Z`），否则会推出一条不存在的「二次弹起后飘到击球面」的弹道，玩家就站在那里等一颗永远到不了的球 | `docs/history.md` 4.20 |
| 界内弹过后滚出边线不算击球方出界 | 第一落点定局；否则「对手没接到」会被改判成「击球方出界」，得分反过来给对手 | `docs/history.md` 4.16 |
| `park` 不能把随机数拨回种子 | 每分落点会一模一样，对手变成复读机；`reset` 才是「换一局」 | `docs/duel.md` 4.2 |

## 8.5 加新测试的约定

**写法**：`t('现象 → 期望', () => { … })`，名字写清「什么情况下应该怎样」，别只写模块名。断言用 `node:assert`；需要固定序列时用文件里已有的 helper：`flatPose` / `strokeAt` / `placeRacket` / `predictX` / `drive` / `feed` / `qAA` / `quatAxis`，对打那几组用 `flightOf`（复算一条弹道的过网高度 / 到面高度 / 第一落点）与 `armedDuel` + `runFrames`（摆一个活球局再推进若干帧）。`drive()` 按 60fps 推进并返回各类事件计数，整局场景优先复用它。

**时间单位（最容易写错）**：

- `Duel.update(dt, now)`：`dt` 是**秒**，学 `drive()` 传 `1000/60 / 1000`；`now` 是**毫秒**。
- `pose.t` / `stroke.t` / `HIT_WINDOW_MS` / `CONTACT_HOLD_MS` 都是**毫秒**，和 `now` 同一把尺子。
- `ImuTracker.update(gyro, dtMs)`、`SwingDetector` 的 `feed(..., dt=16)` 也是毫秒。
- `physics.advance(ball, dt, onStep)` 的 `dt` 是**秒**，定步长 1/240。

**加模块**：见 8.1 第 2 条，两处编译输入都要加。`onStep` 回调返回 `false` 表示事件已处理，必须 `break`，否则会重复结算。

**场景要像真机，别过度理想化**（详见 `docs/tuning.md` 6.3）：

- 模拟器里球拍**必须真的会转**（绕局部 x 轴，中心扫出 0.3–1.1m）；绕法线转中心不动，等于没测。
- 走位用 `predictX` 做**物理前推**，不能线性外推——落地会削掉约 26% 横向速度；且要限速 0.07m/帧，朝球的**当前**横向走，别做外推。
- 走位别用整条弹道外推：来球中途会落地弹一次，外推会把那一拐算进去，走位容易追过头。
- 样本少的统计断言**不要卡跨度**（4 球的甜区跨度会偶发红），改成「都在盘内 + 不是每球完全一样」。
- 改发球节奏要**放宽所有「等球到面」的窗口**，否则偶发失败，而且看起来像别的问题。

**没有模块级开关了**：11-15 删掉对墙打之后，`physics` 里那个全局的 `wallActive` 和 `shootToLand` 的临时开关一起删了，`Duel` 构造时不再需要关墙。`tests/core.test.cjs` 对打那节开头的注释还留着这件事的来龙去脉——**别再照它去找 `setWallActive`**。

那条坑的教训仍然有效：**用例改全局状态会在十几个分组之后报应**。以后再加全局开关（缓存、随机种子、时钟），记得 `finally` 里还回去。

**随机性**：发球 `vx` 带随机散布，某些漏接只在特定扰动耦合下出现。所以 `npm test` **连跑 3 次**才算稳，`npm run duel-sim` 用 6 个种子；单次通过不作数。

## 8.6 没覆盖什么

- **真机挥拍穿模**：没有真机自动化测试，也没有回放/录像；排查只能靠现场观察 + HUD 瞬时读数（`docs/known-issues.md` 7.4）。
- **浏览器侧一切**：传感器事件、WebRTC/信令（除 `test:signal` 冒烟）、HTTPS 证书、three.js 渲染、HUD、手机端 UI，全都不在 `npm test` 里。
- **对打模式的浏览器侧**：整场线条、对手球拍、相机、比分 HUD、发球区高亮与落点圈、**发球手感（抛球高度、等球落下再挥的节奏、俯角映射的深浅直觉）**，全都只有代码层保证（`npm run build` 能证明的只是能打包）。`pickIntercept` 的**选点策略**（选哪个迎击点最舒服）也只有 `npm run duel-sim` 能反映，单测只钉住「在本方半场」这类不变量。
- **性能与长稳**：帧率、内存、`aimIntoCourt` 的计算开销（回球机每次出球要试一条候选落点阶梯）没有基准测试。
- **位姿是理想化的**：测试走位用物理前推 + 限速，比真人准；姿态用构造的四元数，不含传感器噪声、安装角误差和手部抖动（见 `docs/motion-accuracy.md`）。
- **改常量的联动**：`FACE_*`、`ARRIVE_Y_*`、`HIT_WINDOW_MS` 同时决定判定、回球和测试期望。改之前先读 `docs/tuning.md`，改完按 `AGENTS.md` 第 3 节跑三件事：`npm test` ×3 → `npm run duel-sim` → `npm run build`。
