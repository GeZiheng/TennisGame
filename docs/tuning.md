# 调参不变量与踩过的坑

> 原为 `AGENTS.md` 第 5、6 节，2026-11-09 拆分独立成篇。**改任何常量之前先读这里**。
>
> 这些数不是拍脑袋定的，每一条都对应一类真实故障。踩过的坑按「几何/物理」「位姿时序」「测试」「工具链」「前端」分组，
> 每条都写过一次 bug、修过一次，重踩的成本以小时计。

## 5.3 回球机（`MACHINE_L1/L2/L3`）

喂球不再由物理层自己造。回球机就是一个「假手机」：每帧给位姿，球必须真的碰到它的拍面。
详见 `core/machine.ts` 文件头与 `docs/algorithms.md` 3.7。

| 常量 | 现值 | 不变量 |
|---|---|---|
| `ARRIVE_Y_MIN/MAX` | **1.3 / 1.6** | 送到你击球面时的高度带。**往高调会逼出月亮球**（21.6 米外「落界内 + 爬那么高」的弹道有限），低段实测最好（L1/L2/L3 27/52/81） |
| `arriveTol` | 0.12 | 高度带的容差。默认 0.2 太松——差 20cm 就得靠压手腕去补 |
| `speed`（`aimIntoCourt`） | 8–26 | 从对手底线到玩家拍面要 21.6 米，低于 8 到不了、高于 26 压不住 |
| `maxClear` | 2.8 | 过网高度上限。调高会放宽可行域，但也让回球变成高吊 |
| `reactMs` / `moveSpeed` / `reachX` | 380→240 / 2.6→4.6 / 2.6→3.0 | 三档难度的主要旋钮。**这三样不是打磨，是核心设计**：每次都到位的对手比打不过的更出戏 |
| `cornerProb` | 0.15→0.55 | 打不打刁角。改它会直接改 `duel-sim` 的回合数 |

**改任何一个数之前先跑 `npm run duel-sim` 拿基线**：它数的是「机器能不能连续接球」，
L1 约 1.2 拍、L2 约 4.3 拍。往「更好打」调会让回合数涨，往「更狠」调会让它掉——
两边都是信号，看到单调趋势再决定方向。

## 5.5 自动走位（`AUTO_MOVE_DEFAULTS`）

三个自由度：`x`（横向）、`z`（纵深）、`y`（握点升降 = 屈膝/举拍）。**`y` 不是可选的补丁**——没有它，球到面高度和拍面的差只能靠 `z` 去凑，人会被拖到场外去「等球掉下来」。

| 常量 | 现值 | 不变量 |
|---|---|---|
| `speed` / `speedZ` | 4.8 / 3.6 | 一帧最多挪这么多，否则看起来是瞬移 |
| `deadband` | 0.05 | 小于它不动，避免贴球左右抖 |
| `maxX` | **3.9** | 单打边线 4.115，留 20cm 免得踩线。原来 3.0，够不着小斜线 |
| `minZ` / `maxZ` | **HIT_Z−3.0 / HIT_Z+1.0** | 前端放到网前 3m：短球会在 z≈−8 落地、z≈−1.4 二次落地判死，不往前迎就永远等不到。后端只到底线内 1m，再往后是「被球牵着退」 |
| `minGripY` / `maxGripY` | **0.70 / 1.65** | 深屈膝到举拍。低于 0.70 拍面到不了 0.70m 的贴网球；高于 1.65 拍面会出 HUD |
| `incomingVz` | 0.6 | 前进速度低于它不算「朝我来的球」。**别靠预测器返回 null 兜**，横向飘的球照样算得出穿面点 |
| `PAST_MARGIN` | 0.15 | 球越过拍面平面这么多就站住认了这一拍，不再回头追 |

| `speedYSlow` | **1.8** | 预位阶段的升降速度。20cm 走完约 110ms，看得见「在抬」 |

## 6.1 几何 / 物理

- **`sweepFace` 的判据必须是盘形，不是穿平面**。掠射时球心不穿平面但球体压到拍线，按穿平面判会漏 = 穿模。
- **不能用点判定**，必须线段求交。高速球在两帧之间穿过拍面，两端都不在椭圆内。
- **`v × ω` 不能写成 `ω × v`**。写反上旋会往上飘，看着「也挺像那么回事」，但旋转玩法全废。单测钉了一条。
- **撞网必须用碰撞事件判断**，不能用位置跨越。碰撞后位置被修正回网前，`p[2] <= NET_Z` 永远不成立。
- **静止球要提前返回**，否则每秒刷 240 个 ground 事件，音效和粒效被引爆。
- **`advance` 的 `onStep` 返回 `false` 必须 break**。球被接住后速度为 0，继续推进会往下掉一点，还可能重复触发碰撞。
- **`sampleCrossings` 必须按「两次落地即判死」截断，且判据要和 `duel` 同源**（`bounces >= 2 && at[2] > NET_Z`）。少了它，采样会推出一条「二次弹起后飘到击球面」的弹道——那条弹道在真实物理里不存在，规划器却会把人放在终点站着等。坑的形状是「走位看起来到了正确位置、球却凭空消失」，会误判成走位或判定 bug。注意计数要从 `ball.bounces` 起算：来球往往已经弹过一次，只数「从现在起」会数漏。
- **发球判定不能用 `sweepFace`**。竖直抛球 + 竖直拍面时球是**沿着**平面走的，`n0/n1` 永远同号，一次都判不到。用球形判定（`tossContact`），并且只认下落段。
- **同一个「可及范围」只能有一个数**。`reachX` 曾经在预测过滤里是 `+0.6`、在站位夹取里是原值，中间那条缝里的球「看着能碰到、判定从没碰到过」。凡是 `reachLimit()` 能算出来的，别手写第二份。

## 6.2 位姿与时序

- **球拍是「握点 + 朝向」，不是「拍面中心 + 朝向」**。后者屏幕上拍子只转不平移，玩家会立刻察觉不对。
- **凡是「拍面在哪」都用 `faceCenter(pose)`**，不要用 `pose.pos`。握点到中心差 0.6m。
- **渲染与判定必须用同一份 pose**。各算一份就是「看着碰到、判定说没有」。
- **不要用拍面中心的位移估走位速度**。那里面混着挥拍旋转（手腕一转 4 m/s），会把球瞄到半米外。
- **重瞄的目标不要写成「拍面中心 + 本球偏移」**。玩家跟着球挪半步会形成正反馈，球越推越远。
- **模拟器的挥拍时机不要用整条弹道外推**。来球中途还会落地弹一次，整条弹道外推会把那一拐算进去。用 `tta = (HIT_Z - z)/vz`。

## 6.3 测试与模拟器

- **模拟器里球拍必须真的会转**。改造前位姿全程同一个 Q，只有 omega 在变，于是「挥拍甩走拍面」这条真机主路径 0 覆盖——单测全绿、端到端模拟全过、真机全漏。现在绕**局部 x 轴**转，中心扫出 0.3–1.1m。绕法线转是不行的：中心不动，等于没测。
- **测试里的走位别用整条弹道外推**。拍面会跟着球走，走位再叠加预测会互相带偏，球到面时偏到盘外。走位要限速（0.07m/帧）且朝球的**当前**横向。
- **测试走位要用物理前推（`predictX`）**，不能用线性外推：落地会削掉 26% 横向速度。
- **偶发漏接要多种子复现**。发球 `vx` 随机，只在特定扰动耦合下出现。单种子跑过不代表没问题。
- **改发球节奏要放宽所有「等球到面」的测试窗口**。否则偶发失败，而且看起来像别的问题。
- **样本少的统计断言不要卡跨度**。4 球的甜区跨度会偶发红，改成「都在盘内 + 不是每球完全一样」。
- **模拟器里发球的挥拍方向必须和拍面平行**。`shotFromStroke` 的旋转来自 `face × head` 的切向分量；两者一错开就是侧旋，球会被甩出 1.5m。发球落点仍然合法（判在发球区里），但到对面击球面时已经飘出 `reachX`——表现是「每一分都是发球直接赢」，看起来像判定 bug。
- **模拟器的握点行程要取 `AUTO_MOVE_DEFAULTS`**，不要写死 `RACKET_POS[1]`。那个是 11-13 之前的旧模型：按它夹，「接不到球」会被误判成回球机的问题，实际是测试玩家比真机矮了一截。
- **模拟器的跑速和站位边界也要取 `AUTO_MOVE_DEFAULTS`**。11-15 放开边界之后（`maxX` 3.9 → 5.6），脚本若不按 `maxX` 夹，就会替真机打出「跑到 6 米外接球」这种不存在的能力，门禁跟着失真。

## 6.4 类型与工具链

- **TS 闭包赋值会 narrowing 成 `never`**（`let x: T | null = null` 在回调里赋值，之后读出来是 never）。解法：包一层 reader 函数，或把状态装进对象 `const st = { n: 0 }`。
- **TS commonjs 产物的 `exports.x =` 可以 monkey-patch**。这是抓内部输入的神器（例如替换 `physics.aimIntoCourt` 记录机器每次回球的真实参数）。
- **四元数用半角**：`[0, cos(θ/2), sin(θ/2), 0]` 才能得到 θ 倾斜。写成 `cosθ` 会得到两倍角度。
- **Windows 下 `execFileSync('npx.cmd')` 会失败**，要直接调 `node_modules/typescript/bin/tsc`。
- **Node 的递归删除可能被安全拦截器挡住**，测试脚本改成不删目录、直接覆盖。

## 6.5 前端 / 环境

- **`hidden` 属性会被 `display:flex` 覆盖**，要 `[hidden]{display:none!important}`。
- **`.diag` 类名在大屏和手机端撞过**，大屏改用 `.linkpanel`。写新组件前先 grep 类名。
- **不能 `Torus + scale` 做椭圆拍框**，会压扁管截面。要采样点 → 曲线 → `TubeGeometry`。
- **拍线不能用浅色**，浅背景上会消失。
- **微信 WebView / 非 HTTPS 静默拦截传感器**，不报错，只是没有数据。

## 6.6 玩法几何（11-15）

- **抛球点不能锚在「拍面中心」**。拍面中心在握点外 0.6m，位置由**手机朝向**决定：竖握在头顶、横握在胸前 0.6m 外。同一句「抛球」于是抛到三个地方，玩家把拍子举到头顶时球不在那儿。锚点必须取**握点**（`SERVE_STRIKE_UP/FWD`）。
- **判定中心要和抛球点同源**。只改抛球不改判定 = 球抛到打不到的地方；只改判定不改抛球 = 看得到球从拍边飞过却算命中。两者都从 `serveStrike(pose)` 出来。
- **拍子是双面的，法线必须归一化**。`shotFromStroke` 的 `alignment = face·FORWARD` 是**有符号**的：反手时设备 +z 翻到身后，`alignment ≈ −1`，走「拍面背对」分支 → 球飞回自己半场。几何判定（`sweepFace`）对符号不敏感，所以「碰得到、但接不回去」是这个问题唯一的症状。
- **横移/纵深的边界是「站位」不是「落点」**。3.9 那个值按「站在线上不算出界」定的，而那是**球**的规则。真实球员接边线球会跑出边线一两米；卡在场内 = 边线球必失。
- **可站范围一放开，跑速必须跟着放开**。范围决定「能不能到」，速度决定「来不来得及」；只放一个会造出一类假解：规划器选中了那个点，但 `need > p.t` 永远不合格，最后退回兜底。
- **瞄准窗口太窄时先压灵敏度，不要改判据**。发球左右合法窗口 15.6°（偏 8° 就出区）是几何事实；把偏角映射到区宽能「解决」，但等于把「发错区」这条规则删了。压缩灵敏度（`YAW_GAIN`）保留方向感和失误。
