# 网球体感 · P1 对墙打

手机当球拍，大屏对着练习墙打。手机只负责**姿态**和**挥拍**，球的物理、碰撞、音效全在大屏算。

当前进度：P0（链路 + 姿态）已验收，P1（挥拍 → 弹道 → 击球 → 对墙打）已跑通，五种力度档位端到端模拟零漏接。

---

## 怎么跑起来

### 第一次

```bash
npm install
npm run dev:https
```

`dev:https` 会先生成本地 CA 和服务器证书（`.cert/`），再起 HTTPS 服务。终端会打印这样的信息：

```
服务器证书仍然有效（IP 未变：192.168.x.x）

  ➜  Local:   https://localhost:5174/
  ➜  Network: https://172.x.x.x:5174/    vEthernet (WSL)
  ➜  Network: https://192.168.x.x:5174/  以太网
```

> **地址不止一个。** 装了 WSL / Docker / VMware 的机器会多出 `172.x`、`10.x` 的虚拟网卡，手机连那些地址一定打不开。**认准后面写着「以太网」「WLAN」「Wi-Fi」的那一条**——上面例子里是以 `192.168` 开头的那一条。

不用自己判断：`make-cert.mjs` 会单独打印一行「手机访问 → https://192.168.x.x:5174/」，大屏二维码里的地址也是同一套逻辑筛出来的（排除了 loopback / vethernet / vmware / docker / wsl，并按 `192.168` > `10` > `172` 排序）。**直接扫码最省事。**

### 每次开打

1. **大屏**（电脑 / 接电视的笔记本）打开 `https://localhost:5174/`
   证书警告点「继续」——红的也不影响玩，想变绿见下面「把红锁变绿锁」
2. **手机连同一个 Wi-Fi**（建议 5GHz），扫大屏中间的二维码
3. 手机上如果提示证书不受信任，选「继续访问」；点「开始挥拍」，**把手机横过来当拍柄握**
4. 大屏左上角出现「连拍」，就可以打了

> **两端必须是同一个服务进程。** 信令房间在内存里，大屏开在 5173、手机连到 5174 是配不上的。用 HTTPS 就两端都用 5174。

二维码里编的是 `https://192.168.x.x:5174/controller.html`，不是 localhost。手机扫不开时，也可以手动把大屏上那串地址敲进去（面板里有「复制」按钮）。

### 不想掏手机，只想看看画面

```bash
npm run dev          # HTTP，5173，不需要证书
```

浏览器打开 `http://localhost:5173/`，然后按 **`M`** 启动本地模拟控制器——它会生成假数据喂进同一条链路（不经过网络），可以先看手感、看 HUD、看特效。

### 全部命令

| 命令 | 作用 |
|---|---|
| `npm run dev:https` | 真机测试用的主命令（HTTPS + 5174 + 自动签证书） |
| `npm run dev` | 纯本地看画面（HTTP + 5173） |
| `npm run build` | 类型检查 + 打包 |
| `npm test` | 核心逻辑单测（105 项，不需要浏览器） |
| `npm run sim` | 端到端模拟：假数据跑完整对拉，验证手感参数 |
| `npm run verify` | 全套验证：单测 ×3 → sim → build，任一步失败即退出（提交前的快检由 git hook 自动跑） |
| `npm run cert` | 只重新签证书（局域网 IP 变了时用） |
| `npm run trust` | 把根证书装进系统受信任库 |
| `npm run test:signal` | 信令房间配对冒烟测试（需先 `npm run dev`） |

## 怎么打

| 动作 | 效果 |
|---|---|
| 拍面朝球场往前挥 | 球向前飞，**拍面朝哪球往哪飞** |
| 向上刷球 | 出上旋，球过网后会往下扎 |
| 向下切球 | 出下旋 |
| 挥得越快 | 球越快（18–32 m/s），音效和特效也更重 |
| 拍面完全背对球场 | 球会往后飞——这不是 bug，打不出去就是打不出去 |

**连拍只在球过网那一刻 +1**，撞网或漏接归零。

### 喂球是「落在你前面、弹起来再过来」

每一球从对面发出后，会落在**你拍面前方 1.55–1.85 米**的位置，弹起来再过来。目标不是「精确送到拍面中心」，而是**弹起后的最高点落在拍面附近一定范围**：横向 ±12cm、高度 ±10cm、前后 0.55–0.85m（`FEED_APEX_DX/DY/BACK_*`）。

设计上为什么必须用弹地球、落点为什么不能再近（抛体运动给出 `FEED_APEX_LEAD=2.4`，
实测见 `scripts/probe-feed-scan2.cjs`），见 `docs/algorithms.md` 3.6 与 `docs/history.md` 4.5。
这里只留玩家用得上的落点对照表：

| 落点距拍面 | 到拍面时的竖直速度 | 顶点位置 | 手感 |
|---|---|---|---|
| 1.2m | +3.2 m/s，急升 | 拍面后 1.1m | 球往上蹿，容易从拍面上方过去 |
| **1.55–1.85m** | **+1.3 ~ +2.0 m/s，缓升** | **拍面后 0.55–0.85m** | 球「送到手上」，落点也够近 |
| 2.2m | ≈ 0，顶点正好在拍面 | 拍面上 | 最稳、最好打，但落点看着远 |
| 3.0m | −3.8 m/s，下落中 | 拍面前 1.1m | 像掉下来，窗口只有 0.06 秒 |

**高度和横向也以发球那一刻的拍面中心为准，但只保证落在「附近」。** 来球高度 = 拍面中心高度（静止握法下是 `RACKET_POS[1] + FACE_CY` = 1.6m）± 10cm，横向在拍面中心 ±12cm 内随机，前后再散 0.55–0.85m——每球都会差十几厘米。

这两个数不是随便取的：判定椭圆的等效半轴是横向 0.203 / 竖直 0.243。散布之所以取 0.12 / 0.10 而不是贴着半轴，是因为横向和竖直会**同时**偏——两轴都取满时合成偏离是 `sqrt((0.16/0.203)² + (0.14/0.243)²) ≈ 0.98`，几乎贴着盘边，再叠上「球到面时拍面还在动」造成的偏差就会偶发判空。0.12 / 0.10 合成后约 0.72，留三成余量，实测甜区读数落在 0.45–0.75：明显散开，但一定在盘内。

为什么不要「精确送中心」：每球都吸在同一个点上，玩家两拍之后就不用看球在哪侧了，接球退化成打地鼠。

**球不会在飞行途中追你。** 球拍是绕握点转的杆子，一挥拍拍面中心就扫出去半米；曾经让球在最后 0.55 秒每帧改方向去追拍面，但那是追踪弹，不是网球。现在球只按自己的弹道飞。

瞄准一共只有两次，都发生在球还没开始这段飞行之前：

1. **发球时**：按「那一刻的拍面中心 + 本球散布」定落点。
2. **我方半场落地弹起的那一刻重瞄**（`aimAfterBounce`）：球本来就要在这里剧烈改向，横挪几厘米看不出来。横向上限 1.6 m/s（2 米飞行约 20cm），纵向 4.5 m/s。

**代价**：挥拍挥到一半拍子转过 30° 以上，或者发球后大幅走开，球就会够不着——这是物理，需要你自己把拍面对准球。`scripts/probe-swing.cjs` 能量出这个缺口有多宽。正常挥拍节奏下不受影响（sim 30/30）。

旧方案「一口气飞到拍面、中途不许落地」为什么必然变成月亮球，以及 `feedBounce`
的单参数二分求解，见 `docs/history.md` 4.5 与 `docs/algorithms.md` 3.6。

### 一个必须知道的规律：越用力，拍面要越平

同样的仰角，挥得越快球飞得越高越远——真实网球就是这样。全力抽击还保持 20° 仰角，球回来时会在 2.35m 的击球上限之上，你只会看到「够不着」。

模拟里仰角从 20° 压到 6°，才能做到满力 36 拍零漏接。所以：

- 球总是从头顶飞过去 → **压低拍面**
- 球总是撞网 → **抬高拍面**

### 大屏键位

| 键 | 作用 |
|---|---|
| `W` `A` `S` `D` | **走位**：前后左右移动站位（也可以用小键盘方向键） |
| `M` | 开 / 关本地模拟控制器 |
| `C` | 重新开始（清连拍） |
| `X` | 静音 / 取消静音 |
| `R` | 清空延迟统计与峰值，并让手机重新标定姿态基准（拍子和手机歪了就按它） |
| `V` | 视觉走位 / 键盘走位对照切换（仅 `?vision=1` 时有用；默认按会提示未启用） |

走位用来**微调**，不是用来追球。发球瞄的是发球那一刻的拍面，站着不动能接到绝大部分球；
但拍面就是真实的 30×38cm 椭圆，球心偏出 25cm 就打空。看到球往边上偏，按住 `A` / `D`
挪半步，就像真的在场上一样。

### 视觉走位（实验，默认关）

不想一只手拿手机、另一只手按键盘时，可以用**笔记本自带摄像头**追身上一个色块，自动做**左右**走位。
前后轴不做（`z` 固定在击球面）。用 `npm run dev:https` 起服务，然后在大屏地址后面加参数：

| 地址参数 | 作用 |
|---|---|
| `?vision=probe` | 只读取证：右上角显示像素质心、推算站位、色块面积、丢失帧，不接管走位 |
| `?vision=1` | 接管左右走位（忽略键盘走位）；`V` 键可临时切回键盘做对照 |
| `?hue=green` | 换标记颜色：`magenta`（默认）/ `green` / `blue` / `yellow` / `red`，也可写 0–360 数字 |
| `?flip=1` | 左右方向反了就加它（部分前置摄像头回传镜像帧） |
| `?range=1.2` | 视觉模式的站位半幅（米），默认 1.2；键盘模式仍是 ±3.0 |
| `?preview=0` | 关掉取帧预览 |

> 参数加在**大屏**地址上，手机端 `controller.html` 不用改。若大屏地址已带 `?room=XXXX`，
> 参数要用 `&` 拼（如 `...?room=AB12&vision=probe`），别再写第二个 `?`。

标记物贴在**胸口或肩**（别挂手腕，转体会让腕部画弧），8–10cm 见方、高饱和、哑光，和背景颜色区分开。
其余参数（`tol` / `minarea` / `tau`）、完整取证步骤和判据见 `docs/vision.md`。

> **注意：这条通道还没真机验证过**。`npm run verify` 只测了纯计算部分，跑不到摄像头和 DOM。
> 第一次上机请先用 `?vision=probe`：往左走一步确认读数方向、原地挥 5 拍看波动，数字稳了再接 `?vision=1`。
> 默认不加参数时，游戏行为和以前完全一样。

## 面板怎么读

### 左上角：连拍 HUD

大字是当前连拍，下面一行是最好成绩、上一拍球速、上旋/下旋类型。橙色的那行字是击球反馈（比如「挥晚了」）。

### 左下角：链路面板

上半是**击球诊断**，打不到球、或者觉得手感黏时看这六个数：

```
挥拍 12 · 到面 12 · 时差 晚 43ms · 甜区 34% · 出球 0ms · 拍面 右6°
```

| 现象 | 结论 |
|---|---|
| **挥拍 = 0** | 角速度没上来。看手机端「角速度」标记是不是「姿态差分」 |
| 挥拍 > 0，**到面 = 0** | 球压根没碰到拍面，物理或阶段卡住了 |
| 时差 **超过 ±150ms** | 挥早了或晚了。人反应 250ms 起，先看看是不是网络抖动 |
| **甜区 = 没碰到** | 球从拍子旁边飞过去了。多半是球来时你正好在走位，按 `A` / `D` 迎上去 |
| 甜区 **> 85%** | 打到了，但擦着拍框。还能回去，只是出球方向会歪 |
| **出球 > 40ms** | 球在拍面上停太久，手感会「黏」。正常应该是个位数 |
| **拍面 偏 8° 以上** | 球会往那边偏（放大 0.71 倍，10 米差 1.2m）。不是判定的问题，是握法 |

「甜区」是球打在拍面上的位置：0% 是正中心，100% 是拍框内沿。
这个数就是「严格碰撞」在工作——如果你换了拍面角度或者走错方向，
它会立刻变差甚至变成「没碰到」。

「拍面」是**球拍法线当前指向**相对「正对球场」的偏角，正数偏右、负数偏左；
拍面接近水平时会直接显示「朝上」或「朝下」。**静止持拍、拍面朝球场时应该显示「正」。**
如果一直是 10–15°，那不是传感器不准（β/γ 有重力参考，误差 1–2°），
而是手机在手里的内外旋没和你的「拍面」对上——详见 `docs/motion-accuracy.md`。

「时差」和「出球」是两件事，别混：时差是**挥拍时机准不准**（决定判不判得上），出球是**判上之后球多久才动**（决定手感顺不顺）。时差 0、出球 120ms 的体验依然是「明明打到了，球被吸住一下才弹走」。

下半是链路指标：

| 指标 | 含义 | 及格线 |
|---|---|---|
| **端到端 p50** | 从手机传感器采到这一帧姿态，到它被大屏处理完 | < 50ms 无感；> 90ms 会觉得拍子有惯性 |
| **网络 p50** | 只算 Wi-Fi + 排队这一段 | < 25ms 很好；> 50ms 先治网络 |
| **抖动** | 最差的 5% 比中位数糟多少 | < 30ms |
| **峰值角速度** | 手机陀螺仪有没有被甩到量程外 | < 2000°/s 最好 |

**「端到端」减去「网络」，就是手机那一段**（采样等待 + 发包排队）。差值大说明锅在采样率，不在 Wi-Fi——去手机页面看「姿态 xx Hz」。差值小说明网络是主因。

底部曲线是最近 120 个包的单向延迟，**红色虚线是 100ms**。超过它，玩家会归因为「我打空了」而不是「网络卡了」。

抖动那栏：**< 30ms** 环境健康；**30–80ms** 能玩但会偶发打空，换 5GHz 再测；**> 80ms** 先别调手感，先查网络。

> 数值全是 `—` 说明时钟同步没成功：两端都得刷新页面（手机端不回 pong 的话，单向延迟算不出来）。

### 手机端顶部

三个数字，从左到右是姿态来源（绝对姿态 / 陀螺仪）、**发包率**、**姿态采样率**。

发包率 60–75Hz 是正常的（60Hz 定时器 + 挥拍起势时的补发）。真正决定「球拍跟不跟手」的是**姿态采样率**：低于 45Hz 会标黄，说明这台机器的 `deviceorientation` 只有 25–35Hz——屏幕上的球拍其实是 30fps 的动画，和网络快慢无关。

## 调参入口

所有手感常量都在 **`src/core/court.ts`** 一个文件里，改完 `npm run sim` 就能看到影响：

| 常量 | 现在 | 调它会怎样 |
|---|---|---|
| `SWING_THRESHOLD` | 3.0 rad/s | 往下调更容易触发。你习惯轻挥就调到 2.4 |
| `SPEED_MIN` / `SPEED_MAX` | 18 / 32 | 球速区间。**18 是物理底线**：低于它球从墙上弹回来会擦网或在中场趴下（实测 13–16 全挂），想更慢只能改墙弹性或墙距 |
| `SPEED_GAIN` | 2.4 | 挥拍速度到球速的放大倍数 |
| `HIT_WINDOW_MS` | 150 | 击球时间窗。玩家普遍喊「我明明挥到了」就加大 |
| `FACE_RX` / `FACE_RY` | 0.15 / 0.19 | 拍面半宽/半长。**这两个直接决定可击球面积**，改大 = 变简单 |
| `FACE_MARGIN` | 0.02 | 拍面判定容差。补的是「判定用的拍面比玩家手里的晚 20–60ms」那段位移，给 2cm 让擦框也算命中 |
| `FACE_CY` | 0.6 | 握点到拍面中心的距离（杆长），决定球拍视觉长度 |
| 落地重瞄横向上限 | 1.6 m/s | 约等于 2 米飞行里挪 20cm。**别调大**，否则球在落地瞬间明显横挪，等于把追踪弹加回来 |
| `FEED_APEX_DX` / `FEED_APEX_DY` | 0.12 / 0.10 | 来球顶点在拍面中心周围的横向/高度散布。两轴会同时偏，合成后必须留在判定半轴（0.203 / 0.243）以内，调到 0.16 / 0.14 就会偶发判空 |
| `FEED_APEX_BACK_MIN/MAX` | 0.55 / 0.85 | 顶点落在拍面**之后**多远。和落点绑死：落点 = `FEED_APEX_LEAD` − back。调大 = 落点变近、球更「往上送」 |
| `FEED_APEX_LEAD` | 2.4 | 顶点在落点前方多远（抛体运动决定，实测值）。**别凭直觉估**，改完用 `probe-feed-scan2.cjs` 重测 |
| `RETURN_OFF_TOL` | 0.55 | 回球落点允许偏离拍面中心的比例（1.0 = 盘边）。调大 = 回球更散、更自然；调到 0.9 以上会出现「回球擦着框回来」 |
| `RACKET_POS` | (0, 1.0, 0.3) | 参考握法（手机竖直）下的**握点**位置。拍面中心在它正上方 `FACE_CY`，所以静止时拍面高 1.6m |
| `WALL_Z` / `WALL_H` | -11.9 / 5.2 | 练习墙的位置和高度 |
| `SWING_MAX_MS` | 450 | 超过这个时长判为「转」不是「挥」 |

视觉走位的参数**不在这个文件里**：默认值在 `src/play/vision-math.ts` 的 `VISION_DEFAULTS`，可用 URL 参数覆盖（见上面「视觉走位」一节）。它们只影响实验通道，不参与物理与判定。

`npm run sim` 会跑五档力度（5.5 / 8 / 12 / 18 / 28 rad/s）× 6 个随机种子，输出每档每种的识别次数、击球数、漏接、撞网、连拍。**改完参数第一件事就是跑它**——比真机试快得多。跑多个种子是因为「补偿器选中高吊弧线 → 回球在脚前弹起 → reach」这类漏接只在特定发球扰动的耦合下出现，单种子跑过不代表没问题。

## 手机连不上 / 没反应

### 手机说「这个浏览器没有 DeviceMotion」

球拍端页面底部有环境自检，照着它判断：

| 显示 | 含义 | 怎么办 |
|---|---|---|
| 带「微信 / QQ / 钉钉」 | 在 App 内置浏览器里打开的。WebView 不下发运动传感器，**换 HTTPS 也没用** | 右上角 `⋯`（Android 是 `⋮`）→「在浏览器打开」 |
| `安全上下文 ✗` | 地址是 `http://`，被浏览器静默拦截 | 改用 `npm run dev:https`，扫新二维码 |
| 两个都是 ✓ 但点开还是报错 | 权限被拒，或页面不在前台 | 刷新重新授权；iOS 检查设置里 Safari 的「运动与方向访问」 |

微信这个坑最常踩：默认用微信扫码，页面就停在微信的 WebView 里。iOS 微信甚至不会把 `DeviceMotionEvent` 暴露给网页。

### 为什么手机非要 HTTPS

`http://192.168.x.x` 不是安全上下文，Chrome 和 Safari 都会**静默拦截**运动传感器：不报错，而是干脆不给数据。localhost 例外，所以电脑上看不出来，一上手机就废。

### 手机能连上、能挥拍，但打不到球

先看左下角那四个数（见上面「面板怎么读」）。如果「挥拍」是 0，看手机端仪表区的「角速度」标记：

- 亮起「姿态差分」= 这台机器的 `rotationRate` 不可用，已经自动走姿态差分的兜底（能正常玩，只是峰值略软）
- 一直是 `rotationRate` 但挥拍数不动 = 角速度确实没上来

如果是下面这两种，都不是故障，是打法：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 球粘在拍面上，过一会儿才掉下去 | 挥拍时机差得远（差 200ms 以上），冻结等不到事件 | 看 HUD 的「时差」，往前或往后半个节拍 |
| 球从拍子上方整整齐齐飞过去 | 拍面仰角太大，越用力越明显 | 压低拍面（见「越用力，拍面要越平」） |
| 球从身子旁边过去 | 真的没站对，或者发球之后连续走了两米以上（盯人每秒只改 1.2 m/s） | 停下等这一球 —— 下一球会重新瞄你 |
| 球擦着拍框掉下来，没弹回 | 没挥拍，或者挥晚/挥早了 200ms 以上 | 看 HUD 的「时差」；这一球已经判漏接了，等下一球 |

「到面高度」也能直接读数：超过 2.0m 说明来球偏高，下一拍提前压平拍面。

### 如果连不上

点对点直连失败通常是这三个原因，按顺序排查：

1. **路由器开了 AP 隔离**（访客网络几乎都开），两台设备互相不可见
2. **手机连的是访客 Wi-Fi / 蜂窝网络**，和大屏不在同一个子网
3. Chrome 的 mDNS 候选地址在部分路由器上不生效

换到 5GHz 主网络、关掉 AP 隔离，基本能解决。

### 如果球拍的方向整体转了 90°/180°

只有一个旋钮：`src/core/attitude.ts` 里的 `EARTH_TO_WORLD`。它把「地球系（Z 朝上）」翻到「three 世界系（Y 朝上）」，现在是 `Rx(-90°)`。方向整体反了就改成 `Rx(+90°)`，然后 `npm test` 里那几项姿态测试会立刻告诉你哪一项对不上。

## 把红锁变绿锁（可选）

默认是自签名证书，浏览器只认信任链，所以显示「不安全」。现在改成自己当一个 CA：

```bash
npm run cert     # 生成本地根证书 + 用它签发服务器证书（dev:https 会自动跑）
npm run trust    # 把根证书装进当前用户的受信任根证书库
```

装完**完全重启浏览器**（不是刷新），电脑端就没有红锁了。

手机要单独装一次（根证书在电脑上，不在手机上）：

1. 手机浏览器打开 `https://192.168.x.x:5174/ca.crt` 下载
2. **iOS**：设置 → 已下载描述文件 → 安装；然后 设置 → 通用 → 关于本机 → 证书信任设置 → 打开对「Tennis P0 Local CA」的**完全信任**
3. **Android**：设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书 → 选刚下载的文件

撤销：`certmgr.msc` → 受信任的根证书颁发机构 → 找到「Tennis P0 Local CA」删除；手机上删掉对应描述文件即可。

> 这个根证书只签发 `localhost` / `127.0.0.1` / 你的局域网 IP，私钥在 `.cert/ca-key.pem`（已在 `.gitignore` 里）。不要拷到别的机器上。

装不了证书也有替代方案：**mkcert**（`mkcert -install`）或者**内网穿透**（`cloudflared tunnel --url http://localhost:5174`，拿到真实域名和真实证书，手机零配置）。

**换球拍模型**：运行时只加载 `public/models/racket.glb`，判定始终是 `src/core/racket.ts`
里那块椭圆盘，模型一根线都不参与碰撞。`scene.ts` 按 `FACE_RX / GLB_FRAME_HALF_X`、
`FACE_CY / GLB_FACE_CY` 双轴缩放对齐判定盘；换模型只改这两个常量，**不要动 `FACE_*`**
