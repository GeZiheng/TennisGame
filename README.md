# 网球体感 · P1

手机当球拍，大屏打网球。手机只负责**姿态**和**挥拍**，球的物理、碰撞、音效全在大屏算。

**只有一种模式：与脚本回球机对打。**

| 启动 | 端口 | 对面是什么 |
|---|---|---|
| `npm run dev:https` | 5184（HTTP 版 5183） | 一台脚本回球机，会跑位、会回球、会打空 |

对墙打曾经是另一种模式（另一个端口、另一个页面），11-15 删掉了 —— 见 `docs/history.md` 4.27。
手机端一直是同一个页面。

当前进度：P0（链路 + 姿态）已验收；P1（挥拍 → 弹道 → 击球）已跑通；
对打模式（真实赛制 分 → 局 → 盘、发球、回球机、整场渲染）代码层已完成，**浏览器与真机未验**；11-15 按真机反馈改过抛球/反手/走位三处，同样未复验。

## 怎么跑起来

### 第一次

```bash
npm install
npm run dev:https
```

`dev:https` 会先生成本地 CA 和服务器证书（`.cert/`），再起 HTTPS 服务。终端会打印这样的信息：

```
服务器证书仍然有效（IP 未变：192.168.x.x）

  ➜  Local:   https://localhost:5184/
  ➜  Network: https://172.x.x.x:5184/    vEthernet (WSL)
  ➜  Network: https://192.168.x.x:5184/  以太网
```

> **地址不止一个。** 装了 WSL / Docker / VMware 的机器会多出 `172.x`、`10.x` 的虚拟网卡，手机连那些地址一定打不开。**认准后面写着「以太网」「WLAN」「Wi-Fi」的那一条**——上面例子里是以 `192.168` 开头的那一条。

不用自己判断：`make-cert.mjs` 会单独打印一行「手机访问 → https://192.168.x.x:5184/」，大屏二维码里的地址也是同一套逻辑筛出来的（排除了 loopback / vethernet / vmware / docker / wsl，并按 `192.168` > `10` > `172` 排序）。**直接扫码最省事。**

### 每次开打

1. **大屏**（电脑 / 接电视的笔记本）打开 `https://localhost:5184/`
   证书警告点「继续」——红的也不影响玩，想变绿见下面「把红锁变绿锁」
2. **手机连同一个 Wi-Fi**（建议 5GHz），扫大屏中间的二维码
3. 手机上如果提示证书不受信任，选「继续访问」；点「开始挥拍」，**把手机横过来当拍柄握**
4. 大屏左上角出现比分和「对手发球」，就可以打了

> **两端必须是同一个服务进程。** 信令房间在内存里，大屏开在 5183、手机连到 5184 是配不上的。用 HTTPS 就两端都用 5184。

二维码里编的是 `https://192.168.x.x:5184/controller.html`，不是 localhost。手机扫不开时，也可以手动把大屏上那串地址敲进去（面板里有「复制」按钮）。

### 不想掏手机，只想看看画面

```bash
npm run dev          # HTTP，5183，不需要证书
```

浏览器打开 `http://localhost:5183/`，然后按 **`M`** 启动本地模拟控制器——它会生成假数据喂进同一条链路（不经过网络），可以先看手感、看 HUD、看特效。

### 全部命令

| 命令 | 作用 |
|---|---|
| `npm run dev:https` | 真机主命令（HTTPS + 5184 + 自动签证书） |
| `npm run dev` | 纯本地看画面（HTTP + 5183） |
| `npm run build` | 类型检查 + 打包 |
| `npm test` | 核心逻辑单测（155 项，不需要浏览器） |
| `npm run core` | 只把 `src/core` 编译到 `.tmp-duel`（诊断脚本都用它，独立跑一次即可） |
| `npm run duel-sim` | 对打模拟：3 档 × 6 种子，验回球机能不能连续接球、能不能接住发球 |
| `npm run verify` | 全套验证：单测 ×3 → duel-sim → build，任一步失败即退出（提交前的快检由 git hook 自动跑） |
| `npm run cert` | 只重新签证书（局域网 IP 变了时用） |
| `npm run trust` | 把根证书装进系统受信任库 |
| `npm run test:signal` | 信令房间配对冒烟测试（需先 `npm run dev`） |

## 怎么打

| 动作 | 效果 |
|---|---|
| 拍面朝球场往前挥 | 球向前飞，**拍面朝哪球往哪飞** |
| 向上刷球 | 出上旋，球过网后会往下扎 |
| 向下切球 | 出下旋 |
| 挥得越快 | 球越快（18–32 m/s），音效和特效也更重 |
| 反手（手背朝网） | 和正手**完全一样**——拍子是双面的，球只看有没有碰到拍线 |
| 拍框正对来球（拍面侧着 90°） | 球会横着飞——这不是 bug，撞框了就是撞框了 |

**一分只在三个时刻结束**：落地、撞网、飞出范围。中间不给「漏接」的即时判定——球从你身边过去了，
比分要等它落地才动，晚半秒左右，但不会出现「明明出界了却判我得分」（`docs/duel.md`）。

### 来球是回球机打的，它瞄的是「高度带」

对面那台机器每次回球都瞄**你拍面的高度带**：球穿过你的击球面时高度在 `RACKET_POS[1]` 到
`RACKET_POS[1] + 0.3` 之间（1.3–1.6m）。它**不看**你此刻把拍面放在哪儿——真人会自己去够球，
探针的固定挥拍不会，所以诊断脚本要自己喂球（`scripts/probe-contact.cjs`）。

为什么不能把整段都当目标：拍面中心挂在 0.6m 杆末端，能到 1.3–1.9m，但到面越高，从对手底线
21.6 米外还要「落界内 + 爬那么高」的弹道越少，机器只能打月亮球。实测三档（`npm run duel-sim`）：

| 到面高度带 | L1 / L2 / L3 连续回球数 |
|---|---|
| **1.3–1.6m（现用）** | **27 / 52 / 81** |
| 1.45–1.75m | 22 / 33 / 75 |
| 1.6–1.9m | 26 / 40 / 69 |

低段正好是「手机横着握」时拍面所在的高度，玩家不用为了够球把拍子举过头顶。

**球不会在飞行途中追你。** 球拍是绕握点转的杆子，一挥拍拍面中心就扫出去半米；曾经让球在最后
0.55 秒每帧改方向去追拍面，但那是追踪弹，不是网球。现在球只按自己的弹道飞。

**代价**：挥拍挥到一半拍子转过 30° 以上，或者大幅走位，拍面就会从球路上扫开——这是物理，需要你
自己把拍面对准球。`node scripts/probe-contact.cjs` 能量出这个缺口有多宽（当前读数：斜握 0.13m、
竖握 0.40m、横握 0.30m，都在挥拍姿态下），见 `docs/history.md` 4.27。


### 一个必须知道的规律：越用力，拍面要越平

同样的仰角，挥得越快球飞得越高越远——真实网球就是这样。全力抽击还保持 20° 仰角，球回来时会在 2.35m 的击球上限之上，你只会看到「够不着」。

模拟里仰角从 20° 压到 6°，才能做到满力 36 拍零漏接。所以：

- 球总是从头顶飞过去 → **压低拍面**
- 球总是撞网 → **抬高拍面**

### 大屏键位

| 键 | 作用 |
|---|---|
| `W` `A` `S` `D` | **手动走位**：前后左右移动站位（也可以用小键盘方向键）；一按就接管，松手交回自动 |
| `F` | 自动走位开 / 关（默认开，见下） |
| `Z` | **近景 / 全景**切换（默认近景：拍子占画面 40%，方便看击球点） |
| `G` | **挥拍枢轴**开 / 关（默认开：拍子绕腰/肘走弧；关掉就是老样子，绕拍柄底部转） |
| `M` | 开 / 关本地模拟控制器 |
| `C` | 重开一场（比分、发球方、局面全部归零） |
| `X` | 静音 / 取消静音 |
| `R` | 清空延迟统计与峰值，并让手机重新标定姿态基准（拍子和手机歪了就按它） |

### 挥拍怎么走的（默认绕腰/肘）

真网球拍不是绕拍柄底部转的：先转腰带动、击球前一刻肘几乎停住让拍头甩出去、然后随挥再回到
绕身体转。游戏里也是这么走的——你的手机定拍子**朝向**，握着拍子的手会跟着这个朝向绕腰、
击球前一刻切到绕肘，最多挪 18cm。按 `G` 可以关掉做对比。

这样做的代价是拍面在挥拍中会平移一小段，不过判定是按整段扫掠算的，命中率没有变化
（模拟器 396 球 A/B 一致）。**如果手感不对，先按 `G` 关掉，再判断是枢轴还是别的。**

### 自动走位（默认开）

**只要挥拍，不用按键盘。** 游戏沿来球的弹道找我方半场里「拍面正好罩得住球、又来得及走到」
的那个点，横移 5.4 m/s、前后 3.6 m/s 把你搬过去，同时把**握点高度**（举拍 / 屈膝）一起调到位；
没有来球时以 3.2 m/s 回中线、站起来。判定、出球、挥拍检测一行没动。

站位范围是**真的场子加一点边**：横向能跑到单打边线外 1.5m（边线球要跑出去接）、纵深从
网前 4m 到底线内。跑出去的时候相机跟着走，视野会偏——这是 11-15 特意放开的，不是漂移。

三个容易搞错的地方：

**走的是拍面中心，不是握点。** 拍面中心挂在握点前 0.6m 的拍杆末端。握法一横，这根杆子就
横过去，中心落在握点侧方半米 —— 而判定半轴只有 0.24m。所以「把握点对准球」只在拍子竖直时
成立，横着持拍时人站对了、拍面还在半米外。

**前后（z）决定「球到面时有多高」。** 同样的球，站前 30cm 就高 20cm。拍面竖直半轴只有
0.23m，高度差了横向再准也白搭。

**但高度不是靠「退」，是靠「蹲」。** 拍面中心比握点高 0.5–0.6m（竖握就是 0.6m），所以
「球比我拍面低 25cm」这件事，往后退让球掉下来是追不上的 —— 退到场外也差那一截。以前握点
被锁死在 1.3m，斜握/竖握的人几乎每一球都是从拍面**下方**接的。现在这一维由脚本接管：
低球屈膝到 0.70m、高球举拍到 1.65m，横握覆盖 0.70–1.65m 的来球，竖握 1.30–2.25m。

实测（回球机 L1，3 局 × 60s，脚本挥拍 + 真实碰撞几何，只问「球有没有真的进拍面」）：

| 握法 | 改前（只有左右 + 前后） | 现在（多一维握点高度） |
|---|---|---|
| 横着持拍 | 34/38 | **39/39** |
| 斜握约 14° | **2/42** | **38/39** |
| 竖着持拍 | **0/42** | **37/38** |

斜握/竖握改前几乎是零：球全部从拍面下方约 20cm 掠过（判定的竖直半轴只有 0.24m），屏幕上
看着擦到了、判定说没进。这一栏补上之后，「打到了球却没劲」也跟着解释清了：接触点从 1.9m
回到 1.4m 一带，高球掉力的折扣从 0.82 回到 0.91–1.0，回球目标高度也就不用再打月亮球。
剩下没打中的那几球都是**机器接不到我的回球**（它自己跑位失败），不是玩家侧的问题。

关掉的三种方式：按 `F`、地址加 `?auto=0`、或者按住 `A`/`D`（手动永远优先，松手立刻接回来）。
想复现「跑不到位」的手感、或者拍演示视频时用得上。

> 握法偏移是**用你没在挥拍的那几帧**估计的（角速度 > 34°/s 的帧一律不采信）。所以它跟的是
> 你**站着持拍**的握法，不是你挥拍中途的朝向 —— 后半段仍然要自己对准（4.5 撤销「球追拍面」
> 时就是这么定的）。如果开着走位还是「站对了却够不着」，先看 HUD 的「甜区」和「拍面」两个
> 读数：甜区没碰到但站位确实跟着球走，那多半是挥拍时机或握拍角度，不是走位。

## 对打：真实赛制与发球

规则按真实比赛走：**分 → 局 → 盘计分，一盘定胜负**。

| 层级 | 赢法 |
|---|---|
| 分 | 0 / 15 / 30 / 40。40-40 是平分，之后必须**净胜两分**（领先一分显示 `AD`） |
| 局 | 先到 4 分且净胜 2 分。一局结束**换发球方** |
| 盘 | 先到 6 局且净胜 2 局。6-6 进**抢七**（先到 7 分且净胜 2 分），抢七赢下来就是整盘 |

左上角大字是**分**（`0:15` 这样成对显示）、下面一行是**局**。一盘结束之后大字换成最终局分，
按 `C` 重开。

### 发球：球自己抛，拍子得你自己挥

轮到玩家发球时，游戏会把球**竖直往上抛**，但**必须你自己挥拍**才打得出去。

1. 先站到发球位（左右区交替，由这一局已经打了几分决定；一发失误不改站位）；
2. 球自动抛起来，抛在**身体前上方**，顶点约 **3.4m**（比举高的拍子高 1.2m）。
   抛球点跟着你的**身体**走，不跟手机朝向——换个握法也是同一个地方；
3. **等球过了最高点、开始往下落的时候再挥**（约抛出后 0.9 秒），击球点在头顶
   （2.4m 上下）。球在往上升的时候不算打到——那不是发球，那是把球挑起来；
4. 没挥到、或者抛出去 3 秒还没打，就是一次失误。**每分有两次机会**，二发再失误就是
   双误，这一分归对手。

### 必须发到「斜对角的那个区」

发球不是「界内就行」，得落在**斜对角的发球区**里。地面上会有一块绿色的区域，那就是
这一发该去的区；你拍面此刻指向的落点是一个圈：

| 圈的颜色 | 意思 |
|---|---|
| 绿 | 按现在的拍面，球会落进正确的区 |
| 红 | 会失误（发到另一半区、或者压线外） |

**怎么瞄**：

- **左右**看拍面的**水平朝向**——拍面朝哪边，球就往哪边。这个**不会自动帮你修正**：
  瞄到另一半区就是失误，这是规则的一部分。合法窗口是 23°，够你瞄，也够让你失误；
- 如果结算时手机是**屏幕朝天**的（举高手机最自然的握法），准星换成**拍框朝向**，
  因为这时拍面法线没有水平分量，按它算出来的方向是噪声；
- **深浅**看拍面的**俯角**——压得越多球越短，抬得越平球越深。整段俯角都落在有效的
  发球区里，所以你只需要操心左右。

发球的那一拍不用太狠，挥到了就行（速度下限比正常回球低）。

### 键位

`WASD` / `F` / `Z` / `G` / `C` / `X` / `R` 全部照旧。区别只有两点：

- 轮到**对手发球**时不用管站位，站好等球就行；你手动走位仍然优先；
- 轮到**你发球**时，站位由游戏接管（发球是站位固定的动作，一边跑一边发不是网球），
  挥拍之后才交回给你。

## 面板怎么读

### 左上角：比分 HUD

大字是**这一分的比分**（`0:15` 这样成对显示），下面一行是**局分**、上一拍球速、上旋/下旋类型。
橙色的那行字是提示：「你发球 · 一发 · 右区」「出界了」「这盘结束」这类。

### 左下角：链路面板

上半是**击球诊断**，打不到球、或者觉得手感黏时看这六个数：

```
挥拍 12 · 到面 12 · 时差 晚 43ms · 甜区 34% · 出球 0ms · 拍面 右6°
```

| 现象 | 结论 |
|---|---|
| **挥拍 = 0** | 角速度没上来。看手机端「角速度」标记是不是「姿态差分」 |
| 挥拍 > 0，**到面 = 0** | 球压根没碰到拍面，物理或阶段卡住了 |
| 时差 **超过 ±150ms** | 挥早了或晚了。人反应 250ms 起，先看看是不是网络抖动 |
| **甜区 = 没碰到** | 球从拍子旁边飞过去了。自动走位开着还这样，多半是挥拍时机太早/太晚（看「转角」），或握拍角度偏得多；先把 `F` 关掉确认站位有没有跟着球。斜握/竖握时拍面中心比握点高 0.5–0.6m，脚本会把握点压到 0.70–1.65m 去对准，若还是「差一点点」，先看 HUD 的「拍面」偏角 |
| 甜区 **> 85%** | 打到了，但擦着拍框。还能回去，只是出球方向会歪 |
| **出球 > 40ms** | 球在拍面上停太久，手感会「黏」。正常应该是个位数 |
| **拍面 偏 8° 以上** | 球会往那边偏（放大 0.71 倍，10 米差 1.2m）。不是判定的问题，是握法 |

「甜区」是球打在拍面上的位置：0% 是正中心，100% 是拍框内沿。
这个数就是「严格碰撞」在工作——如果你换了拍面角度或者走错方向，
它会立刻变差甚至变成「没碰到」。

「拍面」是**球拍法线当前指向**相对「正对球场」的偏角，正数偏右、负数偏左；
拍面接近水平时会直接显示「朝上」或「朝下」。**静止持拍、拍面朝球场时应该显示「正」。**
如果一直是 10–15°，那不是传感器不准（β/γ 有重力参考，误差 1–2°），
而是手机在手里的内外旋没和你的「拍面」对上——详见 `docs/motion-accuracy.md`。

「时差」和「出球」是两件事，别混：时差是**挥拍时机准不准**（决定判不判得上），出球是**判上之后球多久才动**（决定手感顺不顺）。时差 0、出球 120ms 的体验依然是「明明打到了，球被吸住一下才弹走」。

下半是链路指标：

| 指标 | 含义 | 及格线 |
|---|---|---|
| **端到端 p50** | 从手机传感器采到这一帧姿态，到它被大屏处理完 | < 50ms 无感；> 90ms 会觉得拍子有惯性 |
| **网络 p50** | 只算 Wi-Fi + 排队这一段 | < 25ms 很好；> 50ms 先治网络 |
| **抖动** | 最差的 5% 比中位数糟多少 | < 30ms |
| **峰值角速度** | 手机陀螺仪有没有被甩到量程外 | < 2000°/s 最好 |

**「端到端」减去「网络」，就是手机那一段**（采样等待 + 发包排队）。差值大说明锅在采样率，不在 Wi-Fi——去手机页面看「姿态 xx Hz」。差值小说明网络是主因。

底部曲线是最近 120 个包的单向延迟，**红色虚线是 100ms**。超过它，玩家会归因为「我打空了」而不是「网络卡了」。

抖动那栏：**< 30ms** 环境健康；**30–80ms** 能玩但会偶发打空，换 5GHz 再测；**> 80ms** 先别调手感，先查网络。

> 数值全是 `—` 说明时钟同步没成功：两端都得刷新页面（手机端不回 pong 的话，单向延迟算不出来）。

### 手机端顶部

三个数字，从左到右是姿态来源（绝对姿态 / 陀螺仪）、**发包率**、**姿态采样率**。

发包率 60–75Hz 是正常的（60Hz 定时器 + 挥拍起势时的补发）。真正决定「球拍跟不跟手」的是**姿态采样率**：低于 45Hz 会标黄，说明这台机器的 `deviceorientation` 只有 25–35Hz——屏幕上的球拍其实是 30fps 的动画，和网络快慢无关。

## 调参入口

场地与球拍常量都在 **`src/core/court.ts`**，走位代价权重在 `src/core/auto-move.ts`，回球机在 `src/core/machine.ts`。改完跑 `npm run duel-sim` 看影响：

| 常量 | 现在 | 调它会怎样 |
|---|---|---|
| `SWING_THRESHOLD` | 3.0 rad/s | 往下调更容易触发。你习惯轻挥就调到 2.4 |
| `SPEED_MIN` / `SPEED_MAX` | 18 / 32 | 你的出球速度区间。`SPEED_MIN` 低于 18 时 `shotFromStroke` 会把它抬回去——过网余量不够 |
| `SPEED_GAIN` | 2.4 | 挥拍速度到球速的放大倍数 |
| `HIT_WINDOW_MS` | 150 | 击球时间窗。玩家普遍喊「我明明挥到了」就加大 |
| `FACE_RX` / `FACE_RY` | 0.15 / 0.19 | 拍面半宽/半长。**这两个直接决定可击球面积**，改大 = 变简单 |
| `FACE_MARGIN` | 0.02 | 拍面判定容差。补的是「判定用的拍面比玩家手里的晚 20–60ms」那段位移，给 2cm 让擦框也算命中 |
| `FACE_CY` | 0.6 | 握点到拍面中心的距离（杆长），决定球拍视觉长度 |
| `RACKET_POS` | (0, 1.3, 0.3) | **握点**（胸口中线）。拍面中心在它沿拍柄 `FACE_CY` 处：竖握 1.9m、横握 1.3m。**这个数直接决定横握时拍面多高**，也是回球机到面高度带（`ARRIVE_Y_*`）的基准 |
| `ARRIVE_Y_MIN/MAX`（`machine.ts`） | 1.3 / 1.6 | 回球机送到你击球面时的高度带。**改之前先跑 `npm run duel-sim`**：往高调会逼出月亮球 |
| `SWING_MAX_MS` | 450 | 超过这个时长判为「转」不是「挥」 |

`npm run duel-sim` 跑三档难度 × 6 个种子，数「回球机能不能连续接球」：L1 约 1.2 拍、L2 约 4.3 拍（截断在 L2）。**改完参数第一件事就是跑它**——比真机试快得多。跑多个种子是因为漏接只在特定扰动的耦合下出现，单种子跑过不代表没问题。

## 手机连不上 / 没反应

### 手机说「这个浏览器没有 DeviceMotion」

球拍端页面底部有环境自检，照着它判断：

| 显示 | 含义 | 怎么办 |
|---|---|---|
| 带「微信 / QQ / 钉钉」 | 在 App 内置浏览器里打开的。WebView 不下发运动传感器，**换 HTTPS 也没用** | 右上角 `⋯`（Android 是 `⋮`）→「在浏览器打开」 |
| `安全上下文 ✗` | 地址是 `http://`，被浏览器静默拦截 | 改用 `npm run dev:https`，扫新二维码 |
| 两个都是 ✓ 但点开还是报错 | 权限被拒，或页面不在前台 | 刷新重新授权；iOS 检查设置里 Safari 的「运动与方向访问」 |

微信这个坑最常踩：默认用微信扫码，页面就停在微信的 WebView 里。iOS 微信甚至不会把 `DeviceMotionEvent` 暴露给网页。

### 为什么手机非要 HTTPS

`http://192.168.x.x` 不是安全上下文，Chrome 和 Safari 都会**静默拦截**运动传感器：不报错，而是干脆不给数据。localhost 例外，所以电脑上看不出来，一上手机就废。

### 手机能连上、能挥拍，但打不到球

先看左下角那四个数（见上面「面板怎么读」）。如果「挥拍」是 0，看手机端仪表区的「角速度」标记：

- 亮起「姿态差分」= 这台机器的 `rotationRate` 不可用，已经自动走姿态差分的兜底（能正常玩，只是峰值略软）
- 一直是 `rotationRate` 但挥拍数不动 = 角速度确实没上来

如果是下面这两种，都不是故障，是打法：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 球粘在拍面上，过一会儿才掉下去 | 挥拍时机差得远（差 200ms 以上），冻结等不到事件 | 看 HUD 的「时差」，往前或往后半个节拍 |
| 球从拍子上方整整齐齐飞过去 | 拍面仰角太大，越用力越明显 | 压低拍面（见「越用力，拍面要越平」） |
| 球从身子旁边过去 | 真的没站对，或者发球之后连续走了两米以上（盯人每秒只改 1.2 m/s） | 停下等这一球 —— 下一球会重新瞄你 |
| 球擦着拍框掉下来，没弹回 | 没挥拍，或者挥晚/挥早了 200ms 以上 | 看 HUD 的「时差」；这一球已经判漏接了，等下一球 |

「到面高度」也能直接读数：超过 2.0m 说明来球偏高，下一拍提前压平拍面。

### 如果连不上

点对点直连失败通常是这三个原因，按顺序排查：

1. **路由器开了 AP 隔离**（访客网络几乎都开），两台设备互相不可见
2. **手机连的是访客 Wi-Fi / 蜂窝网络**，和大屏不在同一个子网
3. Chrome 的 mDNS 候选地址在部分路由器上不生效

换到 5GHz 主网络、关掉 AP 隔离，基本能解决。

### 如果球拍的方向整体转了 90°/180°

只有一个旋钮：`src/core/attitude.ts` 里的 `EARTH_TO_WORLD`。它把「地球系（Z 朝上）」翻到「three 世界系（Y 朝上）」，现在是 `Rx(-90°)`。方向整体反了就改成 `Rx(+90°)`，然后 `npm test` 里那几项姿态测试会立刻告诉你哪一项对不上。

## 把红锁变绿锁（可选）

默认是自签名证书，浏览器只认信任链，所以显示「不安全」。现在改成自己当一个 CA：

```bash
npm run cert     # 生成本地根证书 + 用它签发服务器证书（dev:https 会自动跑）
npm run trust    # 把根证书装进当前用户的受信任根证书库
```

装完**完全重启浏览器**（不是刷新），电脑端就没有红锁了。

手机要单独装一次（根证书在电脑上，不在手机上）：

1. 手机浏览器打开 `https://192.168.x.x:5184/ca.crt` 下载
2. **iOS**：设置 → 已下载描述文件 → 安装；然后 设置 → 通用 → 关于本机 → 证书信任设置 → 打开对「Tennis P0 Local CA」的**完全信任**
3. **Android**：设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书 → 选刚下载的文件

撤销：`certmgr.msc` → 受信任的根证书颁发机构 → 找到「Tennis P0 Local CA」删除；手机上删掉对应描述文件即可。

> 这个根证书只签发 `localhost` / `127.0.0.1` / 你的局域网 IP，私钥在 `.cert/ca-key.pem`（已在 `.gitignore` 里）。不要拷到别的机器上。

装不了证书也有替代方案：**mkcert**（`mkcert -install`）或者**内网穿透**（`cloudflared tunnel --url http://localhost:5183`，拿到真实域名和真实证书，手机零配置）。
